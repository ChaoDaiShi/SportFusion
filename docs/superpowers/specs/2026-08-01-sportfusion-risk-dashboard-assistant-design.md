# 体融识界风险驾驶舱与智能研判系统设计规格

状态：待用户书面审阅  
日期：2026-08-01  
适用项目：体融识界 · SportFusion  
设计范围：可视化风险驾驶舱、风险事件中心、智能问答、可信降级与成果输出

## 1. 设计目标

本轮优化服务于比赛展示，也要经得起统计部门、体育管理部门和研究人员的实际使用。评委进入首页后，应在 30 秒内看懂平台解决的问题、模型带来的测算差异及当前风险；专业用户可以继续下钻，核验企业文本、特征、权重、模型版本和计算日志。

系统围绕一条业务链组织内容：

1. 企业数据治理；
2. 体育业务边界识别；
3. 经营活动比重测算；
4. 区域与分业态规模估算；
5. 模型验证、风险研判与政策输出。

风险驾驶舱承担首屏叙事。智能问答不是独立客服，而是这条业务链的自然语言入口。

### 1.1 成功标准

- 首页同时展示模型识别结果、规模测算结果、传统方法差异和模型性能。
- 每条风险均有触发条件、证据、影响范围、当前状态和可执行动作。
- 问答可以读取当前页面上下文，联动筛选、图表、企业明细和报告任务。
- 关键结论附数据批次、模型版本、计算依据或企业样本引用。
- 真实数据、历史快照和演示数据有清晰标识，禁止静默混用。
- 比赛演示在后端或大模型异常时仍可完成，但界面必须说明当前数据状态。
- 全部中文界面不使用 emoji、机器人吉祥物、夸张渐变或无意义的“AI 科技感”装饰。

### 1.2 本轮不做

- 不重写现有 NLP 与规模测算算法。
- 不引入账号、权限、多人协作或审批流。
- 不建设通用知识库后台。
- 不增加与赛题无关的运营、营销或商业化模块。

## 2. 赛题要求映射

赛题将算法效果与效率设为 40 分，因此模型验证不能藏在报告或二级弹窗中。产品一级导航和首页摘要必须显示准确性、异常输入表现、运行时间和资源消耗。

| 赛题要求 | 产品落点 | 首屏证据 |
|---|---|---|
| 数据清洗、文本预处理、标签标注 | 数据过程管理 | 数据批次、质量状态、处理进度 |
| 体育业务边界识别 | 企业边界识别 | 体育企业数、类型分布、低置信度企业 |
| 经营活动比重测算 | 经营比重测算 | 企业占比、特征贡献、权重版本 |
| 产业规模与产值估算 | 产业规模分析 | 总规模、分业态规模、区域分布 |
| 传统行业代码法对比 | 规模测算对比 | 低估差异、增量企业、增量产值 |
| 模型有效性验证 | 模型性能评估 | Precision、Recall、MAE、异常输入测试 |
| 运行时间和资源消耗 | 模型性能评估 | 单万条耗时、峰值内存、批次日志 |
| 政策建议与落地方案 | 智能决策问答、报告中心 | 研判结论、专题快报、政策摘要 |
| 可追溯、可复现 | 数据过程追踪 | 数据版本、规则、参数、模型、计算日志 |

## 3. 用户与演示场景

### 3.1 优先用户

- 比赛评委：关注问题是否成立、算法是否有效、成果是否完整。
- 政府监管与产业管理人员：关注区域风险、统计偏差和政策建议。
- 企业与研究分析人员：关注企业级证据、测算方法和复现过程。

### 3.2 三分钟演示路径

1. 打开统计监测驾驶舱，说明模型比传统行业代码法多识别的企业和规模差异。
2. 点击一个高风险区域，地图、趋势和企业明细同步筛选。
3. 打开风险详情，查看触发阈值、原始证据和模型版本。
4. 向智能研判系统提问，展示带来源的归因结果。
5. 执行校正测算并生成专题快报预览。
6. 进入模型性能评估，展示准确性、异常输入和资源消耗。

## 4. 信息架构

一级导航按业务过程组织，避免沿用“上传、图表、导出”这类工具式菜单。

### 4.1 监测总览

- 统计监测驾驶舱
- 风险事件中心

### 4.2 核心分析

- 企业边界识别
- 经营比重测算
- 产业规模分析
- 区域结构洞察

### 4.3 可信验证

- 模型性能评估
- 数据过程追踪

### 4.4 成果应用

- 智能决策问答
- 报告与成果中心

现有数据管理、企业识别、测算对比、产业大屏和报告导出页面保留其业务能力，但路由命名、页面标题和入口需要并入上述结构。

## 5. 视觉系统

### 5.1 视觉方向

页面采用浅色驾驶舱结构：中心态势图承担主叙事，两侧放置差异、风险与研判信息，下方提供研究级明细。界面需要有比赛展示所需的记忆点，但不能做成常见深色科技大屏。

### 5.2 颜色

- 主背景：米白 `#F4EFE4`
- 卡片背景：暖白 `#FFFDF8`
- 主文字：墨黑青 `#1E2B31`
- 主操作：钴蓝 `#3157D6`
- 高风险：朱红 `#E75B43`
- 中风险与提醒：明黄 `#EFB63A`
- 正常、通过与可信来源：松石绿 `#00A58C`
- 辅助分析：紫色 `#7657D5`

颜色只用于风险等级、状态、图表分组和关键操作。普通卡片不使用高饱和底色。

### 5.3 字体与图形

- 中文字体优先使用 PingFang SC、Microsoft YaHei 和系统无衬线字体。
- 数字使用等宽或稳定宽度的数字特性，避免指标刷新时跳动。
- 图标采用统一线性图标，不使用 emoji 或拟人头像。
- 地图、趋势和表格使用清晰的标签，不能只靠颜色传达等级。
- 动画限于筛选联动、抽屉进出和加载反馈，单次时长控制在 180–240 ms。

## 6. 统计监测驾驶舱

### 6.1 页面结构

1. 顶部：页面标题、区域、年度、数据状态和“生成成果报告”。
2. 业务链：数据治理、边界识别、比重测算、规模估算、验证决策五个阶段。
3. 指标区：体育企业数、估算规模、传统方法低估差异、模型准确率。
4. 驾驶舱主体：左侧显示测算差异与重点风险，中部显示区域规模与风险双图层，右侧放置智能研判摘要。
5. 结果核验台：在边界识别、比重测算、规模对比和异常输入测试之间切换。

### 6.2 筛选联动

统一筛选上下文包含：

```ts
interface AnalysisContext {
  region: string
  year: string
  category?: string
  riskType?: RiskType
  riskLevel?: RiskLevel
  selectedEnterpriseIds: string[]
  selectedRiskId?: string
  dataVersion: string
  modelVersion: string
}
```

点击区域、业态、风险或企业时，页面只更新相关组件；筛选条件显示在顶部，支持逐个移除和一键清空。进入智能问答时，同一上下文随请求发送。

## 7. 风险事件中心

### 7.1 风险类型

```ts
type RiskType =
  | 'enterprise_boundary'
  | 'industry_structure'
  | 'data_quality'
  | 'model_performance'
  | 'measurement_gap'

type RiskLevel = 'high' | 'medium' | 'watch'

type RiskStatus =
  | 'new'
  | 'pending_verification'
  | 'analyzing'
  | 'pending_action'
  | 'resolved'
  | 'monitoring'
```

企业识别风险、产业结构风险、数据与模型风险是三条主线。传统方法与模型差异扩大时，系统生成测算偏差事件，便于比赛展示和统计部门复核。

### 7.2 统一风险对象

```ts
interface RiskEvent {
  id: string
  title: string
  type: RiskType
  level: RiskLevel
  status: RiskStatus
  score: number
  confidence: number
  region: string
  category?: string
  enterpriseIds: string[]
  triggeredAt: string
  updatedAt: string
  deviationScore: number
  impactScore: number
  evidenceScore: number
  evidence: RiskEvidence[]
  suggestedActions: RiskAction[]
  provenance: DataProvenance
}
```

风险分值由偏离程度、影响范围和证据可信度组成。第一版使用后端已配置的权重，不在前端写死计算规则。前端只展示分项得分、总分和触发阈值。

### 7.3 交互闭环

风险自动触发后进入“新发现”。用户打开详情时，地图、趋势和企业表同步定位。核验完成后可以进入智能研判，运行校正测算或生成专题快报。每次状态变化记录操作时间、处理人、参数和前后指标。

状态流转：

```text
新发现 -> 待核验 -> 分析中 -> 待处置 -> 已解决
                                  \-> 持续观察
```

风险详情抽屉包含：触发证据、变化轨迹、关联企业、处置记录和建议动作。用户关闭抽屉后保留筛选上下文，方便横向比较。

## 8. 智能问答与可执行研判

### 8.1 两种界面形态

- 页面内研判面板：回答与当前图表、筛选和风险直接相关的问题。
- 独立分析工作台：处理跨模块归因、重新测算、企业核验和成果生成。

两种形态共享会话、上下文和引用来源。现有左下角吉祥物入口删除。

### 8.2 支持的意图

- 指标解释：解释口径、公式、阈值和图表含义。
- 数据查询：按区域、业态、企业和年度查询结果。
- 对比分析：比较传统方法与本模型、不同区域或不同年度。
- 风险归因：说明触发原因、影响范围和证据可信度。
- 联动操作：应用筛选、定位图表和打开企业明细。
- 计算任务：运行校正测算、重新计算比重或生成对比结果。
- 成果生成：输出企业清单、专题快报、政策摘要和分析报告。

### 8.3 回答结构

```ts
interface AssistantResponse {
  answerId: string
  conclusion: string
  explanation: string
  citations: AssistantCitation[]
  metrics: AssistantMetric[]
  suggestedActions: AssistantAction[]
  warnings: string[]
  dataVersion: string
  modelVersion: string
  fallbackMode: DataMode
}
```

回答顺序固定为：结论、解释、证据、可执行动作。缺少证据时不生成确定性结论；系统说明缺少的数据，并提供补数或替代分析路径。

### 8.4 动作权限

- 可直接执行：页面筛选、切换图层、定位图表、打开明细。
- 需要预览确认：重新测算、生成报告、导出文件。
- 本轮不支持：修改模型全局配置、删除数据、覆盖原始数据。

报告生成前显示内容范围、数据版本、模型版本和目标格式。用户确认后才执行。

### 8.5 流式事件

现有 SSE 通道继续使用，但事件由纯文本扩展为结构化类型：

```text
context_ready
plan_ready
tool_started
tool_finished
answer_delta
citations_ready
actions_ready
completed
error
```

界面显示“正在读取数据”“正在运行测算”等明确状态，不使用无含义的三个跳动圆点或逐字打字特效。

## 9. 数据来源与可信降级

```ts
type DataMode = 'real' | 'cached' | 'demo'

interface DataProvenance {
  mode: DataMode
  datasetId: string
  dataVersion: string
  modelVersion?: string
  updatedAt: string
  isComplete: boolean
  missingFields: string[]
}
```

### 9.1 正常状态

所有组件使用同一真实数据版本。顶部显示数据批次和更新时间，导出文件携带相同元数据。

### 9.2 部分接口失败

优先显示最近一次成功的真实快照，并标注快照时间。组件提供重试和错误详情。旧快照不能标成实时结果。

### 9.3 无真实数据

整页进入演示沙盘，使用同一份可解释演示数据。顶部、问答、报告和导出文件均带“演示数据”标识。不能在同一图表中混合真实值和演示值。

### 9.4 问答服务不可用

基础数据、图表和指标解释继续可用。用户问题保留在输入区，可重试或转为规则说明。系统不返回猜测性回答。

## 10. 前端结构

沿用 Vue 3、Vue Router、Pinia、Element Plus 和 ECharts。页面布局与业务组件自建，Element Plus 负责基础表单、抽屉、弹窗和可访问性能力。

## 11. 后端接口边界

沿用 FastAPI 与现有算法服务。新增聚合接口，不复制底层计算逻辑。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/monitoring/overview` | 驾驶舱聚合数据与来源状态 |
| GET | `/api/risks` | 风险列表、筛选与分页 |
| GET | `/api/risks/{risk_id}` | 风险证据、轨迹与关联企业 |
| POST | `/api/risks/{risk_id}/verify` | 保存核验结论 |
| POST | `/api/risks/{risk_id}/recalculate` | 预览或执行校正测算 |
| GET | `/api/model/metrics` | 准确性、鲁棒性、耗时与内存 |
| GET | `/api/system/data-status` | 数据模式、版本与缺失字段 |
| POST | `/api/assistant/stream` | 结构化 SSE 问答 |
| POST | `/api/assistant/actions/preview` | 预览测算、导出或报告动作 |
| POST | `/api/assistant/actions/execute` | 用户确认后执行动作 |
| POST | `/api/reports/generate` | 生成专题快报或完整报告 |

现有 `/api/chart/dashboard`、`/api/chat/stream` 和模型验证接口可作为第一版数据源，由新的聚合层适配。

## 12. 错误处理

- 页面级错误只在核心数据完全不可用时出现；局部失败在对应卡片内处理。
- 所有错误提供可执行下一步：重试、查看快照、进入演示沙盘或查看指标定义。
- SSE 中断后保留已完成回答和引用，显示中断位置并允许继续。
- 报告生成失败保留任务参数，用户可以重试，不重复创建成功任务。
- 接口返回的数据版本不一致时，页面暂停联动并提示刷新，避免跨版本比较。
- 缺失字段、空列表和异常数值需要独立空状态，不以零值冒充真实结果。

## 13. 可访问性与响应式

- 风险等级同时显示文字与颜色。
- 键盘可以进入导航、筛选、风险列表、抽屉和问答输入区。
- 重要图表提供摘要文本和数据表入口。
- 1440 px 及以上显示完整三栏驾驶舱；1024–1439 px 隐藏次要说明；低于 1024 px 改为上下布局。
- 比赛主展示按 1920×1080 优化，同时保证常见笔记本分辨率可用。

## 14. 测试与验收

### 14.1 单元测试

- 风险等级、状态和来源标识映射正确。
- 筛选上下文的增加、删除、清空和路由恢复正确。
- SSE 事件解析、断线恢复和错误状态正确。
- 真实、缓存、演示三种模式不会混用。

### 14.2 组件测试

- 点击地图区域后，指标、图表和表格接收同一筛选条件。
- 点击风险事件后，详情抽屉展示对应证据和版本。
- 高风险不能只靠颜色区分。
- 报告生成与重新测算必须经过预览确认。

### 14.3 接口测试

- 聚合接口包含 `provenance`，版本字段一致。
- 风险详情缺字段时返回明确的 `missingFields`。
- 助手引用的指标和企业均能由引用标识再次查询。
- 报告任务具备幂等键，重试不产生重复成果。

### 14.4 端到端场景

1. 真实数据完整：完成驾驶舱下钻、问答、校正测算和报告预览。
2. 单个图表接口失败：显示最近真实快照并成功重试。
3. 后端不可用：整页进入演示沙盘，所有输出均有演示标识。
4. 大模型不可用：数据查询可用，问答不生成猜测性结论。
5. 异常输入：缺失企业文本、超长文本和噪声文本均有测试结果。
6. 比赛演示：在三分钟内完成第 3.2 节的完整路径。

### 14.5 视觉验收

- 页面不出现 emoji、吉祥物、机器人头像和紫蓝渐变背景。
- 米白底色和明艳强调色在浅色投影环境中仍有足够对比度。
- 1920×1080 首屏不出现纵向滚动，核心数字和模型指标完整可见。
- 抽屉、弹窗和表格没有文字截断、重叠或布局跳动。
- 空状态、错误状态和演示模式均有明确文案。

## 15. 实施优先级

第一阶段先完成可演示闭环：应用外壳、统计监测驾驶舱、风险事件中心、页面内研判面板、独立分析工作台、模型性能摘要和演示保障。

第二阶段补齐核验写入、校正测算、报告任务、数据过程追踪和完整模型评估。若时间有限，第二阶段功能可以先提供只读结果和任务预览，但不能用无效按钮伪装完成。

## 16. 已确认决策

- 使用深色驾驶舱的信息骨架，但整页改为米白浅色视觉。
