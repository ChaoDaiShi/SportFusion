# SportFusion 系统可视化报告完善设计

## 1. 目标与交付物

在不改变原报告核心结构、统一数据口径和既有实证结论的前提下，直接完善用户提供的《体融识界·SportFusion——多元经营背景下企业体育业务识别与区域产业规模估算（基于文本—代码双通道与可解释证据融合技术）_系统口径同步.docx》。

最终交付一份新的 Word 文档，保留源文件不变。新文档应将第四章现有“图4-2 SportFusion Web系统演示路径与截图预留”替换为同一发布候选版本的真实系统页面，并补充必要的图题、图注、页面说明和内容审查结果。

## 2. 内容范围

系统演示采用图4-2（a）—（i）的多分图结构，按完整统计工作流组织九个页面：

1. 统计监测驾驶舱；
2. 企业数据治理；
3. 企业边界识别；
4. SportShare经营比重测算；
5. 区域与业态规模分析；
6. 模型性能评估；
7. 人工复核工作台；
8. 动态企业名录；
9. 报告与成果导出。

若当前系统没有与某一名称完全对应的独立路由，应使用功能上最接近、能够证明该工作环节的真实页面，不为凑齐九张而虚构页面。

## 3. 截图与演示处理

- 所有截图来自同一代码版本、同一批次上下文和同一数据模式，优先使用正式批次；如只能使用演示模式，必须在图注或页面标识中明确说明。
- 统一使用高清桌面视口，隐藏浏览器地址栏等无关界面，保证导航、数据模式、核心指标、证据链和主要操作区可辨认。
- 图像处理仅限裁切、等比缩放、轻度锐化、统一留白、局部放大、序号和重点标注，以及遮蔽本地路径或非报告必要的敏感信息。
- 禁止修改系统数值、图表走势、模型状态、数据模式、批次信息或错误状态；禁止把演示数据包装成正式实证结果。
- 页面存在真实空状态、降级状态或artifact缺失时，优先切换到具有可用数据的合法批次；无法消除时应如实标注，不通过图像处理伪造成功状态。

## 4. Word 编排

- 保留报告封面、目录、五章主体和附录结构，不重写既有章节逻辑。
- 在第四章4.1中原图4-2位置插入九张分图，采用每页约两张的纵向编排；图像与各自分图题注保持同页，避免截图过小或跨页脱离题注。
- 使用“图4-2（a）……”至“图4-2（i）……”编号，不改变后续既有图表编号。
- 在分图组后补充一段总体分析，按“创新方法＋实现技术＋解决痛点＋可核验效果”的逻辑说明系统如何把同一批次结果串联为治理、识别、测算、复核、名录和导出闭环。
- 仅对第四章与截图直接相关的表述做局部修订；若发现全文存在与系统当前口径直接冲突的内容，应优先校对源数据和代码，再作最小改动或明确边界说明。

## 5. 内容审查

审查至少覆盖：

- 页面名称、导航顺序与报告所述演示路径是否一致；
- 正式、演示、测试数据模式是否被清楚区分；
- SportScore与SportShare职责是否混淆；
- 2022年四川省体育产业总产出2,170.80亿元等统一口径是否与正式批次一致；
- 8,950家候选、8,016家传统直接代码覆盖、934家增量候选等核心集合关系是否与报告一致；
- 截图中的批次、版本、Provenance和锁定状态是否足以支撑可追溯说明；
- 是否出现无依据的对比实验、消融实验或性能数字；缺失证据继续使用“待补真实实验数据”或报告既有的边界说明；
- 图题、图注、正文引用、分页、图片清晰度和版式是否规范。

审查发现仅属于系统实现的问题时，本任务记录问题并避免在报告中错误表述，不擅自扩大范围修改系统代码。

## 6. 验证与完成标准

1. 九个工作流环节均由真实系统页面或明确标注的真实状态支撑；
2. 所有演示处理可追溯，未改动数据结论；
3. 源文档保持不变，输出为新的DOCX文件；
4. 输出文档能够由Word兼容工具正常打开；
5. 使用标准DOCX渲染工具生成逐页PNG，并逐页检查截图清晰度、文字截断、图片变形、题注脱页、表格破损、页眉页脚和分页；
6. 最终报告不存在明显内容矛盾；无法核实的实验结果不得补造数字。
